Metrics & why

  • WER / CER via jiwer 4.0 on symmetrically normalised reference and hypothesis (whisper-normalizer: English normaliser for EN, Basic + diacritic-removal for tonal languages, frozen before scoring). WER is the standard ASR metric; CER is added because it is fairer to tonal/agglutinative languages where a single morpheme error inflates WER.
  • Downstream money-outcome — the metric that matters for a fintech: feed each transcript to the actual invoice pipeline and classify the result as exact, off-by-small, catastrophic (a confidently wrong total), blocked (guard asked a question), or ready. WER alone does not tell you whether the money was right.
  • Latency & RTFx — usability on a mid-range phone on mobile data.

Downstream task — did the invoice come out right?

Each transcript was run through Sautice's real invoice pipeline (heuristic extraction → deterministic executor). Outcome classes on the 8 recorded invoice utterances:

ModelExactOff-smallCatastrophicBlocked (asked)Ready
Intron Sahara10071
ElevenLabs Scribe v142026
Whisper large-v3-turbo00080

The headline safety result: zero catastrophic errors for every model. No model ever caused a confidently-wrong invoice — because the deterministic core refuses to guess and asks a clarifying question instead (the "blocked" column). Whisper's transcripts were too garbled to extract a transaction at all, so everything was blocked (safe, but unusable). This downstream set is small (n=8) and does not separate Sahara from Scribe on its own; it validates the safety design and motivates the accuracy findings above. In production the streaming path plus in-market vocabulary is expected to move more Sahara cases from "blocked" to "ready".

Qualitative findings per model

Intron Sahara — chosen for the product

  • Strengths: best or tied-best on every Nigerian category; strongest on Pidgin and Nigerian accents by a wide margin; near-zero hallucination (6 insertions); native code-switched language codes (yo/ig/ha/pcm); 100% completion.
  • Weaknesses: highest latency in batch file mode (~19 s) — mitigated in the product by using streaming for live partials and the file API only as a dropout fallback.

ElevenLabs Scribe v1

  • Strengths: excellent on clean English/read speech (best CER); fast (3.2 s); 100% completion.
  • Weaknesses: degrades on Pidgin (0.495 WER) more than Sahara; no Nigerian code-switched language selection; a third-party dependency outside the challenge's Sahara requirement.

Whisper large-v3-turbo (Groq)

  • Strengths: fastest (2.5 s, 1.33× realtime); fine on clean English (0.121).
  • Weaknesses: collapses on Nigerian-accented (0.669) and Pidgin (0.779) speech; substitution-heavy (confident mishears); 7.4% of clips failed to return usable text.

Conclusion

For Nigerian, code-switched, market speech, Intron Sahara is the most accurate model tested and the only one built for Nigerian language codes; Scribe is a close general-purpose second but weaker on Pidgin, and Whisper is unsuitable for this domain. Sahara is therefore the product's primary engine, with a synchronous Sahara file fallback for transport reliability. Across all models, the deterministic money layer produced zero catastrophic invoices — the correct safety property for a fintech built on imperfect ASR.

Limitations & next steps. Pilot scale (68 clips, 8 downstream). Next: expand to ≥300 clips per language with native-speaker reference audits, add Gemini, and evaluate the live streaming path (not just file mode) for latency.
